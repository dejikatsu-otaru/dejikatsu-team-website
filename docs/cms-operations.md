# CMS 運用ガイド

## 管理画面

本番: https://dejikatu.com/admin/

固定OwnerのIDは `Master`。パスワードはすでに安全な場所へ保存したものを使う。
初期設定をやり直す必要はない。Bootstrap Tokenの再登録や初期SQLの再実行もしない。

## 記事を追加・公開する

1. 「記事を追加」を開く。
2. タイトル・説明・カテゴリ・画像の説明を入力する。サブタイトルは任意。
3. 本文を入力する。太字・斜体・見出し・文字色・リンクを利用できる。
4. 「下書きを保存」で非公開のまま保存する。
5. 内容を確認して「公開する」を押す。トップ、活動紹介、記事専用ページに反映される。

公開中の記事の「変更を保存（公開中）」は、そのまま公開内容を更新する。
非公開で編集したい場合は、先に「公開停止」を押す。
同時に編集された場合は保存が拒否されるため、自分の原稿を別途退避し、再読み込みして確認する。

## Markdown と画像

- Markdown欄に入力すると本文に自動変換される。チェックを外すと自動反映を止められる。
- 自動反映を止めている場合は「Markdownを本文へ反映」で確認する。
- 変換後の本文を直接編集したり、装飾・画像を追加すると、本文を保存する方式へ切り替わる。
  その際Markdown欄は空になるが、変換済みの見出し・リストなどは本文に残る。
- 画像は「本文内画像の説明」を入力し、本文の挿入位置を選んで「画像を追加」を押す。
- 画像はブラウザー内でWebPへ変換してからD1へ保存される。画像を外部変換サービスへ送らない。
- 長辺1920px以下、1画像1.5MB以下、本文内30種類まで。容量制限を超える画像は保存されない。
- 本文は入力10,000文字以内・変換後HTML25,000文字以内。画像を多く含むと上限に早く達する。
- 公開ページの最下部には作成者の本名・役職と、ほかのお知らせが最大3件表示される。

## 公開停止・削除

- **公開停止**: 公開サイトから非表示にし、管理画面には残す。
- **削除**: 管理画面で復元できる削除。復元直後は非公開になる。
- **完全削除（非推奨）**: 固定Owner・マスターのみ利用可能。通常の削除を行った後に表示される。
  この操作は管理画面から復元できない。
- 移行した本文なしのお知らせは、タイトル・説明・サブタイトル・リンクなどを編集できる。
  PDF・参加申込など既存のリンクを不用意に消さない。本文なし形式を新しく作る機能はない。

## アカウントと権限

| 権限 | 操作できる範囲 |
| --- | --- |
| 固定Owner | すべての管理操作。Ownerは固定で、移譲・削除・停止不可 |
| マスター | 全記事とアカウント管理。ただし他のマスターの権限・状態を変更できず、マスターを追加できない |
| オペレーター | 全記事の作成・編集・公開・公開停止・通常削除。アカウント管理と完全削除は不可 |
| リポーター | 自分が作成した記事だけを作成・編集・公開・公開停止・通常削除 |

「アカウント管理」からID・本名・役職・権限を設定すると、有効化用の一回限りのリンクが発行される。
安全な方法で本人へ送り、本人がパスワードを設定する。期限切れ時はリンクを再発行する。
通常マスター間でのパスワード再設定は、承認済みの仕様として可能。
固定Ownerのパスワードはログイン後の「パスワード変更」から本人が変更する。

## 運用上の注意

- 操作せず30分経過、またはログインから8時間経過すると再ログインが必要。
- Freeプランと承認済みの独自認証方式を利用する。大量アクセス時の無料枠超過リスクは残る。
- 現在は `cms` と `main` のデプロイが同じD1を使う。プレビューでの編集も本番データの変更になる。
- 合成記事やテストアカウントを本番・プレビューに追加しない。動作試験はローカル仮想D1で行う。
- 同じD1を使う間は認証用Secretも両環境で整合させる。値を推測で上書き・再生成しない。
- SQL、Binding、Secret、デプロイ手順は [Cloudflareデプロイ手順](cloudflare-deployment.md) を参照。
